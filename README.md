## 📝 Execution Notes

- Leans array/graph/DP-heavy since those dominate real FAANG loops. If your target companies lean more OOD/system design (e.g., Amazon), consider splitting Day 13 into 2 days.
- Always timebox and state time/space complexity out loud after each solve — that habit matters more than the exact problem set.
- Skim/skip any ★ problem you can already solve in under 10 minutes and bank that time for Days 6, 9, and 11, which tend to run long.
- Missed problems: revisit at the end of Day 13 rather than mid-sprint, to avoid breaking pace.
